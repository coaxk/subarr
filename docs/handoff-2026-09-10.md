## Open, with the next step spelled out

### #515 - bulk verify failures destroyed by the batch's own completion
`runVerifyBatch` returns `{done, errors}`; **both call sites discard it**. The
only render of the count is under `bulkRunning && selectedCount > 0` and
`finish` falsifies both in one commit. Cheapest correct fix: **do not clear the
selection when `errors > 0`**, so failed rows stay ticked and the bar stays
mounted. `swapTrackBulk` already does the right thing with a `window.alert` -
copy that shape. Also in scope: no cancel and no `beforeunload` on an operation
that is now minutes long (nav is plain `<a href>`, so clicking Coverage
mid-batch kills it silently). **Test it through the new jsdom harness.**

### #516 - propagation failures return HTTP 200
`_propagate_to_sonarr` returns `{"attempted": True, "ok": False, ...}` for FIVE
distinct failures, all with a 200. Every frontend caller checks only `r.ok` and
never reads the body, so rows leave Review looking fully successful while
Sonarr was never updated. Opt-in (`SONARR_PROPAGATE_AUDIO_LANG` defaults `"0"`)
so it is not urgent. Also: `audio_lang.py` documents the Sonarr language table
as "cached per process" and **`sonarr.languages()` has no memoization at all** -
fix the cache, not the docstring, because it is ~4 Arr calls + a Bazarr
`update_series` per file and the volume ceiling is gone.

  change, or `git add -A` swallows it. The doc is fixed now and says why.
